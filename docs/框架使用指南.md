# 使用指南

面向"拿到仓库、想尽快写业务"的人。想了解设计取舍看 [架构说明](架构.md)，想看逐项能力索引看 [功能详解](框架功能详解.md)，想抄一个完整功能看 [API 实现示例](API实现示例.md)。

## 1. 这是什么

Electron 45 + Vue 3.5 + TypeScript 5.9 + Vite 8 的桌面应用骨架。克隆下来 `npm install && npm run electron:dev` 就能写业务，不用先补 IPC、配置、日志、主题、路由、测试这些基础设施。

**支持平台**：Windows 10+、Linux（现代桌面）。macOS 不发布、不验证。

**明确的非目标**：自动更新、代码签名/公证、内置遥测/埋点。

## 2. 五分钟跑起来

```bash
# 要求 Node >= 22.12（.nvmrc 与 engines 已锁定）
npm install          # 安装依赖，并自动装好 pre-commit 钩子
npm run electron:dev # 构建主进程 + 起 Vite + 起 Electron
```

`electron:dev` 之后：

- 渲染进程走 Vite 热更新（改 `.vue` 立刻生效）
- 改 `src/main`、`src/preload`、`src/shared` 会自动重建主进程并重启 Electron（`scripts/dev.mjs`）
- 应用关掉 = 开发会话结束

启动后你会看到：应用标题（来自配置 `appName`）、框架信息卡片、「获取系统信息」「调试工具」「配置」三个入口。

> 开发态不会自动打开 DevTools，除非把 `features.developerTools` 设为 `true`。临时调试按 `F12` 或 `Ctrl+Shift+I` 即可。

## 3. 目录速览

| 目录            | 放什么                                 | 关键约束                                                                       |
| --------------- | -------------------------------------- | ------------------------------------------------------------------------------ |
| `src/main/`     | 窗口、托盘、菜单、模块、IPC 处理器     | 有完整 Node 能力，代码最"重"                                                   |
| `src/preload/`  | `contextBridge` 暴露的 API 白名单      | 必须内联通道列表；sandbox 下不能 require 分块                                  |
| `src/renderer/` | 页面、组件、store、composable、主题    | 只能通过 `window.electronAPI` 出圈                                             |
| `src/shared/`   | 类型契约、常量、默认配置、schema、i18n | **不能 import electron**（`shared/utils/index.ts` 是历史例外，别在渲染端引它） |
| `scripts/`      | 开发启动器、钩子安装、冒烟、e2e        | 纯 Node 脚本，无第三方依赖                                                     |
| `docs/`         | 文档                                   | —                                                                              |

## 4. 数据放在哪

| 内容     | 路径（Windows / Linux）                                                                 |
| -------- | --------------------------------------------------------------------------------------- |
| 配置     | `%APPDATA%\electron-vue3-demo\config.json` / `~/.config/electron-vue3-demo/config.json` |
| 配置备份 | 同目录 `config.json.bak`（首次裁剪未知键时生成）                                        |
| 日志     | 同目录 `logs/main.log`                                                                  |
| 插件     | 同目录 `modules/*.{cjs,js}`                                                             |
| 窗口状态 | 就在 `config.json` 的 `window` 字段                                                     |

便携模式或测试：设置 `ELECTRON_USER_DATA_DIR` 指向自定义目录（CI 冒烟就是这么隔离的）。

## 5. 常见任务

### 改应用名 / 标题

- 标题：配置里的 `appName`（首次启动取 `app.getName()`）
- 安装包名：`package.json` 的 `build.productName`

### 加一个页面

1. 新建 `src/renderer/views/FooView.vue`
2. 在 `src/renderer/router/routes.ts` 注册（懒加载）：

```ts
{ path: '/foo', name: 'foo', component: () => import('../views/FooView.vue') }
```

> 404 兜底路由（`/:pathMatch(.*)*`）必须保持在数组最后。

### 加一个 IPC 通道

四处改动，缺一不可（详见 [API 实现示例](API实现示例.md)）：

1. `shared/constants` 加通道常量
2. `shared/types` 的 `IpcInvokeMap` 声明 `{ args, returns }`
3. 在所属核心模块的 `ipcHandlers()` 里声明 `{ channel, handler }`（`IpcManager` 只做聚合与 sender 校验）
4. `preload/index.ts` 加入内联白名单（漏加会直接 `typecheck` 失败）

渲染端调用 `window.electronAPI.invoke('foo:bar', arg)`，参数和返回值都有类型。

### 加一个配置项

`shared/config/defaults.ts`（默认值）→ `shared/types`（类型）→ `shared/config/schema.ts`（白名单）→ 需要 UI 就在 `ConfigPanel` 加控件 → 文案进 `shared/i18n`。

`config:update` 只认 schema 里的键，写错会被拒绝并返回带键路径的错误。

### 加一种语言

`shared/i18n` 里加一份 `AppMessages`，补进 `SUPPORTED_LOCALES`，再在 `ConfigPanel` 加选项。两种语言的键结构有用例守护。

### 改主题色

只改 `src/renderer/styles/theme.css` 的 CSS 变量（`:root` 与 `[data-theme='dark']`）。组件里不要写死颜色。

### 换图标

- Windows：`assets/icon.ico`
- Linux：`assets/icon.png`，**必须是真 PNG 且 ≥512×512**
- 托盘：优先 `icon.ico`，缺失时退到 `icon.png`

### 文件读写

框架**不提供**通用文件通道：`userData/modules` 会在启动时被执行，渲染进程若能任意写文件，就等于留了一条「写插件 → 重启生效」的持久化提权链。

需要落盘时，在自己的主进程模块里用 Node API，路径限制在 `userData` 的专用子目录，并做越界检查：

```ts
const dataDir = path.join(app.getPath('userData'), 'data');
const file = path.join(dataDir, path.basename(name)); // 只接受纯文件名
```

需要用户选文件时，用主进程的 `dialog.showOpenDialog`，不要接受渲染端传来的任意路径。

## 6. 调试

| 场景     | 做法                                                                                      |
| -------- | ----------------------------------------------------------------------------------------- |
| 渲染进程 | DevTools（F12 / Ctrl+Shift+I），或把 `features.developerTools` 设为 true 让启动时自动打开 |
| 主进程   | `npm run electron:start -- --inspect=9229`，然后 Chrome 打开 `chrome://inspect`           |
| 看日志   | `userData/logs/main.log`，渲染端异常也会带 `[renderer]` 前缀写进来                        |
| 启动耗时 | 日志里的 `Startup completed`：`ready` / `modules` / `ipc` / `window` / `total`            |
| 真实链路 | `npm run e2e`（驱动界面走真实 IPC），`npm run smoke`（只验证能启动）                      |

## 7. 打包

```bash
npm run build                 # 主进程 + 渲染进程
npm run electron:build        # 当前平台解包产物
npm run electron:build-win    # Windows NSIS 安装包
npm run electron:build-linux  # Linux AppImage + deb（需在 Linux 上执行）
```

- Windows 用 `icon.ico`；Linux 用 `icon.png`（≥512）
- Linux 的 AppImage/deb 依赖 Linux 工具链（`dpkg`、`fpm`），在 Windows 上打不了
- 不做自动更新（产物里没有 `latest.yml`）、不做签名（未签名会被 SmartScreen / Gatekeeper 提示，属发布决策）

## 8. 常见问题

### 启动报 `Cannot read properties of undefined (reading 'requestSingleInstanceLock')`

终端把 `ELECTRON_RUN_AS_NODE=1` 传给了 Electron（VS Code 等 Electron 系终端常见），Electron 退化成普通 Node。
`npm run electron:dev` 已主动清掉该变量；直接 `electron .` 时手动清：PowerShell `$env:ELECTRON_RUN_AS_NODE=''`。

### 保存配置报 `An object could not be cloned.`

传了 Vue 的 Proxy 给 IPC。渲染端发复杂对象前要 `toPlain()`（`renderer/utils/plain.ts`）。框架内置的配置与日志上报已经处理，自己新增通道时注意。

### 保存配置报「不是已知配置项」

`config:update` 只接受 schema 里的键。先改 `shared/config/schema.ts`，再改默认值与类型。

### 运行时 `Blocked IPC channel`

通道没加进 `preload` 白名单，或改了 preload 但没重新构建。`npm run electron:dev` 会重建。

### `Blocked IPC call from untrusted sender`

页面来源不在白名单：开发态必须是 `http://localhost:5173`（不要用 `127.0.0.1`），打包态必须是 `file://`。

### 托盘图标没出现

Linux 某些桌面没有状态栏，托盘建不起来时框架会**允许直接关窗**（而不是把窗口藏起来）。检查系统是否启用了 AppIndicator 扩展。

### 打包失败

1. 先 `npm run build` 确认能过
2. 检查 `package.json` 的 `build` 配置（`files` / `extraResources` / `icon` 路径）
3. Linux 包必须在 Linux 上打
