# 框架功能详解

> 这是一份**功能索引**：每项能力对应哪块源码、由什么驱动、怎么验证。想了解"为什么这么设计"看 [架构说明](架构.md)，想上手看 [使用指南](框架使用指南.md)。

## 1. 支持范围

| 平台              | 状态                                                                                                             |
| ----------------- | ---------------------------------------------------------------------------------------------------------------- |
| Windows 10+       | 官方支持（托盘、通知、AppUserModelId、NSIS 安装包实测）                                                          |
| Linux（现代桌面） | 官方支持。Ubuntu 24.04 x64 实机已验证启动、渲染、主题、系统信息 IPC、i18n；AppImage/deb 出包与托盘关闭行为待验证 |
| macOS             | 不发布、不验证；`appMenu` 分支保留但属 best-effort                                                               |

**非目标**：自动更新、代码签名/公证、内置遥测/埋点。原因见[路线图](framework-roadmap.md)第 13–15 节。

## 2. 主进程能力

| 能力          | 说明                                                                                                      | 源码                                                     |
| ------------- | --------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 应用生命周期  | 单实例锁、`whenReady`、`before-quit`（模块清理 3 秒超时 + 日志刷盘）                                      | `main/index.ts`                                          |
| 启动打点      | `Startup completed`：`ready` / `modules` / `ipc` / `window` / `total` 毫秒                                | `main/index.ts`                                          |
| 窗口创建      | `show: false` + `ready-to-show`；`did-fail-load` 兜底显示                                                 | `main/managers/window.manager.ts`                        |
| 窗口状态      | `width/height/x/y/maximized` 防抖 300ms 落盘，关闭时立即落盘；离屏坐标丢弃                                | `managers/window.manager.ts`、`managers/window-state.ts` |
| 系统托盘      | 关闭窗口最小化到托盘；图标按 ico → png 顺序取第一个能解码的，全部不可用时按托盘不可用处理（允许直接关窗） | `managers/window.manager.ts`、`managers/tray-icon.ts`    |
| 托盘通知      | 首次关闭提示，或用 `tray.balloonNotificationEnabled` 每次提示                                             | 同上                                                     |
| 应用菜单      | 基于原生 role 的菜单（文字跟随系统语言）；macOS 保留 `appMenu`                                            | `managers/menu.manager.ts`                               |
| DevTools 收口 | 生产态默认移除菜单项并拦截 F12 / Ctrl+Shift+I / Cmd+Alt+I                                                 | `managers/window.manager.ts`                             |
| 导航守卫      | `will-navigate` 白名单 + `setWindowOpenHandler`（仅 https 交系统浏览器）                                  | 同上                                                     |
| 权限默认拒绝  | `setPermissionRequestHandler` 全拒                                                                        | `main/index.ts`                                          |
| 单实例激活    | 第二个实例启动时激活已有窗口                                                                              | `main/index.ts`                                          |

## 3. 配置系统

### 3.1 三层结构

```
shared/config/defaults.ts   唯一默认值（主进程与渲染进程共用）
shared/config/schema.ts     唯一结构描述：白名单 + 类型校验 + 未知键裁剪
main/modules/config.module.ts   落盘：串行队列 + 临时文件 rename 原子写
renderer/stores/config.store.ts 渲染端唯一入口
```

### 3.2 配置项清单（每项都有真实消费方）

| 键                                | 类型 / 默认值                        | 消费方                                                      |
| --------------------------------- | ------------------------------------ | ----------------------------------------------------------- |
| `appName`                         | `string` / 应用名                    | 窗口标题、托盘 tooltip                                      |
| `version`                         | `string` / 应用版本                  | 记录用                                                      |
| `theme`                           | `light` \| `dark` \| `auto` / `auto` | `renderer/theme`：切换 `<html data-theme>`，`auto` 跟随系统 |
| `language`                        | `zh-CN` \| `en-US` / `zh-CN`         | `shared/i18n`：界面文案 + 托盘菜单/通知                     |
| `window.width` / `height`         | `number` / 1200 / 800                | 建窗初始尺寸，限制在最小尺寸与工作区之间                    |
| `window.x` / `y`                  | `number?`                            | 建窗初始位置，不在任何显示器可见区则丢弃                    |
| `window.maximized`                | `boolean?`                           | 首帧就绪后是否最大化                                        |
| `features.developerTools`         | `boolean` / `false`                  | 开发态是否自动开 DevTools；生产态是否放行 DevTools 与菜单项 |
| `tray.hasShownFirstTimeNotice`    | `boolean` / `false`                  | 是否已提示过「最小化到托盘」                                |
| `tray.balloonNotificationEnabled` | `boolean` / `false`                  | 每次关闭都弹气泡                                            |

### 3.3 写入与迁移

- 渲染端 `config:update` → `sanitizeConfigUpdate`：未知键、错误类型、非法枚举、`__proto__` 一律抛错（错误带键路径）
- 合法更新 → `deepMerge` → 入队 → 写 `.tmp` → `rename` 原子替换
- 加载时裁掉 schema 之外的键，首次裁剪前备份 `config.json.bak`，并打日志 `Dropping unknown config keys`

## 4. IPC 通道

全部通道一览（`shared/types` 的 `IpcInvokeMap` 是唯一契约）：

| 通道              | 参数                        | 返回         | 说明                       |
| ----------------- | --------------------------- | ------------ | -------------------------- |
| `ping`            | —                           | `string`     | 连通性自检，返回 `pong`    |
| `system:info`     | —                           | `SystemInfo` | 平台、架构、内存、用户信息 |
| `config:get`      | —                           | `AppConfig`  | 读取完整配置（副本）       |
| `config:update`   | `updates`                   | `void`       | schema 校验后合并落盘      |
| `log:report`      | `level`, `message`, `meta?` | `void`       | 渲染端日志上报，主进程限流 |
| `window:minimize` | —                           | `void`       | 最小化发起调用的窗口       |
| `window:maximize` | —                           | `void`       | 最大化 / 还原              |
| `window:close`    | —                           | `void`       | 关闭发起调用的窗口         |

**已移除**（老读者注意）：`file:read` / `file:write` 不再提供——它能写进 `userData/modules`，
与插件自动加载叠加等于持久化提权链。

每次调用的三层保障：

1. 编译期：`IpcInvokeMap` 校验通道名、参数元组、返回类型
2. preload：内联白名单 + 完整性断言（漏加通道 → `typecheck` 失败）
3. 主进程：`registerHandler` 统一做 sender 来源校验（开发态 `http://localhost:5173` 精确 origin，打包态 `file://` 且拒绝带主机的 URL）

## 5. 渲染进程能力

| 能力     | 说明                                                                        | 源码                                              |
| -------- | --------------------------------------------------------------------------- | ------------------------------------------------- |
| 路由     | `vue-router` hash 模式 + 404 catch-all（兜底路由固定最后注册）              | `renderer/router/`                                |
| 主题     | CSS 变量（`:root` / `[data-theme='dark']`），`applyTheme` 只切 `data-theme` | `renderer/styles/theme.css`、`renderer/theme/`    |
| 多语言   | `useI18n()` 返回 computed 文案，随配置语言切换                              | `renderer/composables/useI18n.ts`、`shared/i18n/` |
| 错误边界 | `AppErrorBoundary` 捕获子树异常，展示错误与重新加载                         | `renderer/components/AppErrorBoundary.vue`        |
| 弹窗     | `Modal`：ESC、Tab 焦点陷阱、焦点归还、滚动锁、`role="dialog"`、`aria-modal` | `renderer/components/Modal.vue`                   |
| 配置面板 | 主题 / 语言 / 功能开关，保存失败显示可读提示                                | `renderer/components/ConfigPanel.vue`             |
| 状态     | `config.store`（配置）；调试面板是页面局部状态，不进全局 store              | `renderer/stores/`                                |
| IPC 封装 | `invoke` 泛型 + `toPlain`（Proxy 转纯数据）+ `reportError`                  | `renderer/utils/`                                 |

## 6. 模块系统

| 项       | 说明                                                                                                  |
| -------- | ----------------------------------------------------------------------------------------------------- |
| 接口     | `Module { name, version?, description?, init(), destroy?() }`（`main/managers/module.types.ts`）      |
| 加载     | 核心模块 `required: true`（失败中断启动）；`userData/modules/*.{cjs,js}` 逐个加载、失败隔离           |
| 日志     | 插件通过 `globalThis.__frameworkLogger` 写入 `main.log`                                               |
| 能力边界 | 只能 `require('electron')` 与 Node 内置模块（打包排除了 `node_modules`），详见[插件开发](插件开发.md) |

## 7. 日志与可观测性

| 层                         | 行为                                                              |
| -------------------------- | ----------------------------------------------------------------- |
| `main/utils/logger.ts`     | 异步串行队列写 `userData/logs/main.log`，`flush()` 等队列清空     |
| `main/utils/app-logger.ts` | 进程级单例：`initLogger` 前回退 console，之后各模块 `getLogger()` |
| 退出路径                   | `before-quit` / `uncaughtException` 先 `flush()` 再退出           |
| `renderer/utils/report.ts` | `reportError` / `reportInfo` / `reportWarning` → `log:report`     |
| `main/ipc/log.handler.ts`  | 级别白名单 + 2000 字符截断 + 10 秒 50 条限流                      |
| `renderer/main.ts`         | `app.config.errorHandler` + `unhandledrejection` 双兜底           |

## 8. 安全默认

| 防线     | 实现                                                                     |
| -------- | ------------------------------------------------------------------------ |
| 进程隔离 | `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`      |
| API 面   | preload 只暴露白名单通道，无任意 `send` / `on`                           |
| 来源校验 | sender 按 `URL.origin` 精确比对（防 `localhost:5173.evil.com` 前缀伪装） |
| 文件能力 | 不提供通用文件通道                                                       |
| 配置输入 | schema 白名单 + 原型键拒绝                                               |
| 内容安全 | CSP 禁 `unsafe-eval`；HMR 的 `ws://` 只在开发态注入                      |
| 导航     | 站外导航拦截、`window.open` 默认拒绝（仅 https 交系统浏览器）            |
| 权限     | Web 权限请求默认拒绝                                                     |
| 调试能力 | 生产态默认收起 DevTools 与其快捷键                                       |

威胁模型与边界见[架构说明第 8 节](架构.md)。

## 9. 命令与门禁

| 命令                                          | 作用                                                                   |
| --------------------------------------------- | ---------------------------------------------------------------------- |
| `npm run electron:dev`                        | 构建主进程 + Vite + Electron；主进程/preload/shared 改动自动重建并重启 |
| `npm run electron:build`                      | 当前平台解包产物                                                       |
| `npm run electron:build-win`                  | Windows NSIS 安装包                                                    |
| `npm run electron:build-linux`                | Linux AppImage + deb（需在 Linux 上执行）                              |
| `npm run typecheck` / `lint` / `format:check` | 静态检查                                                               |
| `npm test` / `test:coverage`                  | 单元与组件测试（105 用例）/ 覆盖率阈值                                 |
| `npm run smoke`                               | 真机冒烟：启动 Electron，校验配置与日志落盘                            |
| `npm run e2e`                                 | 真实交互：驱动界面改配置、切语言，校验整条 IPC 链路                    |

`npm install` 会自动安装 pre-commit 钩子，跑前五项门禁。

## 10. 与旧版本的差异

如果你看过更早的文档，这些能力**已被移除**，不要再照着写：

| 旧能力                                | 现状                                    | 原因                                |
| ------------------------------------- | --------------------------------------- | ----------------------------------- |
| `file:read` / `file:write`            | 移除                                    | 与插件目录叠加成持久化提权链        |
| `BaseIpcHandler` / `IpcResponse` 信封 | 移除                                    | 信封从未跨进程，只是样板            |
| `features.analytics`                  | 移除                                    | 没有遥测实现，勾了不生效            |
| `features.autoUpdate`                 | 移除                                    | 自动更新是明确的非目标              |
| 渲染端 `user.service` 服务层          | 移除                                    | 直接用 store + `invoke`，少一层抽象 |
| IPC 五处注册                          | 改为四处（通道 / 类型 / 注册 / 白名单） | 类型契约合并了常量与签名            |
