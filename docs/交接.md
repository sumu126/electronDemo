## 0. 一句话

这是一个 Electron + Vue3 桌面应用骨架：工程纪律与安全基线高于多数同类模板，**核心模块可以声明 IPC 贡献点**（新增通道仍要改 `constants` / `types` / `preload` 三处）。别把它当 Quasar 那样的全家桶，也别当纯模板。

## 4. 架构地图

```
src/main/            主进程：窗口、托盘、菜单、模块、IPC、日志
├── index.ts                 启动链路（顺序不可随意调整）
├── managers/                window / module / menu / window-state / window-policy / tray-icon / devtools-shortcut
├── ipc/                     各 handler + ipc-contribution 类型 + sender 来源校验 + log 上报
├── ipc-manager/             通道聚合（核心模块贡献 + 重复通道拦截）
├── modules/config.module.ts 配置模块（核心模块，required）
└── utils/                   logger（异步队列）、app-logger（单例）
src/preload/index.ts         白名单（内联，不能 import 共享常量）
src/renderer/                Vue：router / views / components / composables / stores / theme / styles / utils
src/shared/                  types / constants / config(defaults+schema) / i18n / utils(纯函数)
scripts/                     dev.mjs / install-hooks.mjs / smoke.mjs / e2e.mjs
```

**启动顺序**（`main/index.ts`）：单实例锁 → `initLogger` → `whenReady` → 模块初始化（Config 必需）→ 配置注入 WindowManager → IPC 注册 → 权限拒绝 → 应用菜单 → 建窗（`show:false` + `ready-to-show`）→ 启动打点。改顺序前先读 `docs/架构.md` 第 4 节。

**三处契约必须同步**：

1. `shared/types` 的 `IpcInvokeMap`（通道名 + 参数元组 + 返回类型）
2. `preload` 的 `ALLOWED_CHANNELS`（漏加 → 编译期断言失败）
3. 核心模块的 `ipcHandlers()`（`IpcManager` 聚合 + sender 校验 + 重复通道拦截）

## 6. 下一步该做什么（第九轮后已更新）

### P0-1 IPC 注册变成"模块贡献点"（✅ 第九轮已完成）

- `Module` 增加可选 `ipcHandlers()`，贡献类型从 `IpcInvokeMap` 推导
- `IpcManager` 只聚合核心模块通道，保留 sender 校验并拒绝重复通道
- `ConfigModule` 自行声明 `config:get` / `config:update`，内核不再硬编码业务通道
- `userData/modules` 插件不参与收集，避免覆盖核心通道
- 新增通道仍需改 `constants` / `types` / `preload` 三处

### P0-2 平台毛刺三连（✅ 第八轮已完成）

- 窗口图标按平台选择（Linux 优先 PNG），复用 `pickDecodableImage`
- 首帧背景由 `theme` + 系统配色解析，深色启动不再闪白
- 补 `setPermissionCheckHandler`；CSP 增加 `object-src 'none'` 与 `base-uri 'none'`

### P0-3 类型与运行时对齐（✅ 第八轮已完成）

- `AppConfig.language` 已改为 `Locale`，与 schema 枚举一致

### P0-4 日志轮转（✅ 第八轮已完成）

- `Logger` 超过 5 MB 轮转，保留 3 份；`flush()` 与退出刷盘语义不变

### P1（剩余）

- e2e 增加一条"重启后窗口状态恢复"（当前只有配置/主题/语言一条主流程）
- `window.manager` 剩余的托盘菜单接线、状态防抖计时器可继续抽纯函数补测

### 明确不建议

- 崩溃上报：`crashReporter` 必须配 `submitURL`（使用方自己的服务），框架只能预留钩子
- 多窗口：已作为死 API 删除，恢复等于给没人用的代码续命
- 追 Quasar 的功能面：定位不同（骨架 vs 全家桶）

## 7. 踩过的坑（别重踩）

| 坑                         | 现象                                                        | 正确做法                                                                      |
| -------------------------- | ----------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Vue Proxy 过 IPC           | `An object could not be cloned.`                            | 渲染端发复杂对象前走 `renderer/utils/plain.ts` 的 `toPlain`                   |
| `ELECTRON_RUN_AS_NODE`     | Electron 退化成 Node，报 `requestSingleInstanceLock` 未定义 | `electron:dev` 已清除；手动启动时清环境变量                                   |
| Windows 出 Linux 包        | AppImage：`EPERM symlink`；deb：`spawn fpm ENOENT`          | 只能出 `tar.gz`（`--linux tar.gz`），安装包交给 Linux/CI                      |
| smoke 日志竞态             | 偶发"main.log 没有 Main window created"                     | 已改为轮询到目标日志行，**别再退回"只等文件存在"**                            |
| 中文文件用 PowerShell 改写 | 文件名/内容变乱码（`浠庝富...`）                            | 只用编辑工具；确需脚本时用 UTF8 无 BOM                                        |
| CRLF                       | Windows 上 `format:check` 无故失败                          | `.gitattributes` 已统一 `eol=lf`，别删                                        |
| 配置未知键                 | 加载时被裁剪（首次留 `.bak`）                               | 加配置项必须同时改 `defaults` + `schema` + `types`（有 consistency 测试兜底） |
| 覆盖率门禁                 | 删代码后覆盖率下降会让 CI 红                                | 删代码同时删对应测试，或补别的测试；**不要下调阈值**                          |

## 8. 常用命令

```bash
npm run electron:dev      # 开发（主进程/preload/shared 改动自动重启）
npm run typecheck|lint|format:check|test|test:coverage|build
npm run smoke             # 真机启动 + 配置/日志落盘校验
npm run e2e               # CDP 驱动界面：配置保存/主题/语言
npm run electron:build-win    # Windows NSIS
npm run electron:build-linux  # Linux AppImage + deb（需 Linux）
npx electron-builder --linux tar.gz   # 只有 Windows 时的验证包
```

验证顺序建议：`typecheck → lint → test → build → smoke → e2e`（改到渲染端交互或 IPC 契约，e2e 必跑）。

## 11. 外部评审结论（供参考，不必全盘接受）

另一智能体给了约 7/10：工程纪律 8、框架完备度 5.5。我认可其核心判断——**"扩展点仍停留在约定，没有变成机制"**，即第 6 节 P0-1。

两处不认同：

1. 拿 Quasar 对比不公平（UI 全家桶 vs 应用骨架），合理对标是 `electron-vite` / `forge` 的脚手架能力
2. 崩溃上报不算法"缺口"：`crashReporter` 需要接收服务，和自动更新/签名同属使用方负责

它提到而我确认成立的小问题：`language: string` 类型、窗口图标固定 ico、`#ffffff` 背景、缺 `setPermissionCheckHandler`、日志无轮转、`helpers.ts` 死代码、主进程窗口事件无测试。前六项已在第八轮修掉；**P0-1 已在第九轮补上**；主进程窗口事件仍无测试。

- 用户会跳着问"还剩什么/可以了吗"，**要直接给判断和证据**，不要复述已完成项
