# 插件（用户模块）开发约定

框架允许在不改动源码、不重新打包的前提下，往应用里加主进程能力：把 CommonJS 文件放进
`userData/modules/`，启动时会被自动加载。

> 这是**主进程代码**，拥有完整权限。只加载你信任的文件。

## 1. 目录与加载规则

```
%APPDATA%/<应用名>/modules/
├── hello.cjs
└── backup.js
```

- 扩展名只认 `.cjs` 与 `.js`，其它文件忽略
- 必须导出 CommonJS：对象、工厂函数，或带 `default` 的对象
- 目录不存在时跳过，不会报错

三种导出形式都支持：

```js
// 1. 直接导出模块对象
module.exports = { name: 'Hello', async init() {} };

// 2. 工厂函数（需要传参时用）
module.exports = () => ({ name: 'Hello', async init() {} });

// 3. ES 风格的 default
module.exports = { default: { name: 'Hello', async init() {} } };
```

## 2. 模块契约

```ts
interface Module {
  name: string; // 唯一标识，重复注册会被跳过
  version?: string;
  description?: string;
  init(): Promise<void>; // 失败即视为该模块不可用
  destroy?(): Promise<void>; // 应用退出时调用
}
```

- `init` 抛错：**只隔离该模块自身**，应用继续启动
- 核心模块（配置等）失败会中断启动，插件不受此待遇
- `destroy`：退出时逐个调用；整体最多等 3 秒，超时强制退出

## 3. 能力边界（重要）

| 能力                  | 是否可用 | 说明                                                    |
| --------------------- | -------- | ------------------------------------------------------- |
| `require('electron')` | ✅       | 完整主进程 API                                          |
| Node 内置模块         | ✅       | `fs` / `path` / `crypto` / `child_process` …            |
| 第三方 npm 依赖       | ❌       | 打包时排除了 `node_modules`，`require('lodash')` 会失败 |
| 渲染进程代码          | ❌       | 插件运行在主进程，不参与渲染端构建                      |

需要第三方库时有两个办法：

1. 把依赖打成**单文件**再放进 `modules/`（如 `npx esbuild dep.js --bundle --platform=node`）
2. 修改打包配置，把该依赖显式带进产物（会增大安装包，且升级需重新打包）

## 4. 日志

插件不能 import 框架代码，因此提供了一个极简入口：

```js
globalThis.__frameworkLogger?.info('HelloModule starting', { version: '1.0.0' });
```

写入 `userData/logs/main.log`，与框架日志同一条时间线。`console.log` 只在控制台可见。

## 5. 注册 IPC 通道（可选）

插件可以自行 `ipcMain.handle`，但**必须自己做来源校验**，否则就等于绕过了框架的安全默认值：

```js
const { ipcMain } = require('electron');

ipcMain.handle('hello:greet', (event) => {
  const url = event.senderFrame?.url ?? '';

  // 与框架一致：开发态 http://localhost:5173，打包后 file://
  if (!url.startsWith('http://localhost:5173') && !url.startsWith('file://')) {
    throw new Error('Blocked IPC call from untrusted sender');
  }

  return 'hello';
});
```

更好的做法是走框架的通道注册流程（`IPC_CHANNELS` → `IpcInvokeMap` → `IpcManager`），
这样 preload 白名单与类型契约会自动生效；只是那需要改源码重新打包。

## 6. 安全清单

- 只把可信任的插件放进 `modules/`：它能读写文件、起子进程、访问网络
- 不要把 `modules/` 目录暴露给渲染进程（框架也不提供通用文件写入通道）
- 插件里如果要落盘，把路径限制在 `app.getPath('userData')` 下的专用子目录
- 发布前给插件做哈希或签名校验，并在 `init` 里自检

## 7. 示例

完整示例见 [examples/hello-module.cjs](examples/hello-module.cjs)：

```bash
# Windows
copy docs\examples\hello-module.cjs "%APPDATA%\electron-vue3-demo\modules\hello.cjs"
# macOS / Linux
cp docs/examples/hello-module.cjs ~/.config/electron-vue3-demo/modules/hello.cjs
```

下次启动时日志里会出现：

```
[INFO] Loaded user modules: HelloModule
[INFO] HelloModule initialized
```
